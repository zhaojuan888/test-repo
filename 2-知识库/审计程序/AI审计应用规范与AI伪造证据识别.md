## 一、审计人员使用 AI 的规范（事务所侧）

### 1.1 硬红线（中注协 2026-03-05 第二份年报审计业务指引）

| 维度 | 具体要求 | 依据 |
|---|---|---|
| **保密** | 未经客户授权或法律法规允许，**不得将涉密信息输入/上传至公共 AI 平台**；不得向所外第三方披露涉密信息 | 《会计师事务所数据安全管理暂行办法》《职业道德守则》 |
| **环境受控** | 使用 AI 处理客户数据前，必须确保技术环境、数据流转、访问权限**安全且严格受控**，防泄露/滥用/丢失 | 同上 |
| **不替代判断** | AI 使用**不能替代注册会计师专业判断**，**不减轻**对审计意见承担的责任 | 中注协指引 |
| **底稿记录** | 按 **CSA 1131** 在底稿中充分适当记录：使用 AI 的**过程 + 结果 + 对结果的分析与采纳过程** | CSA 1131 |
| **异常须追证** | AI 识别出的异常，**必须采取进一步审计程序**确认是否存在重大错报风险 | 中注协指引 |
| **官方核实** | AI 提供的信息，**可通过官方平台获取的数据核实** | 中注协指引 |
| **不一致时** | 与其他来源证据不一致 → 保持职业怀疑，确定修改/追加哪些程序，并考虑对**审计结论**的影响 | 中注协指引 |
| **业务约定书** | 需与被审计单位就信息技术使用充分沟通，**必要时在约定书中约定条款** | 中注协指引 |

### 1.2 允许 / 禁止场景（可写入所内制度）

| 场景 | AI 可用度 | 说明 |
|---|---|---|
| 财务数据异常波动筛查、科目勾稽校验 | ✅ 可用（辅助） | 结果须人工复核 |
| 合同条款比对、关联交易筛查、资金流水异常分析、内控缺陷初筛 | ✅ 可用（辅助） | 属风险识别环节 |
| 政策法规检索、准则条文查询、案例参考 | ✅ 可用 | **仅限非涉密信息** |
| 凭证抽样、OCR 提取、格式转换 | ✅ 可用 | 抽取样本须可复核 |
| **重大错报风险评估** | ❌ 不得依赖 AI 定论 | 必须注会独立判断 |
| **审计证据充分适当性判断** | ❌ 不得依赖 AI 定论 |  |
| **审计意见类型出具** | ❌ 不得依赖 AI 定论 |  |
| 上传客户财务数据/底稿/个人敏感信息至公共大模型 | ❌ 禁止 | 除非客户书面授权 + 私有化部署 |

### 1.3 底稿记录四要素（每处 AI 辅助程序都要能回答）

1. **输入**：什么数据进去的？完整性与准确性怎么验证的？
2. **工具**：什么工具/模型/版本、做了什么、依据什么？
3. **输出**：工具给出了什么结果？
4. **结论**：我怎么复核的、采纳/不采纳的理由是什么？

> 落地做法：在底稿模板加"AI 辅助程序记录表"字段（工具名+版本+提示词/参数+输出摘要+人工复核人+复核结论+日期），与 CSQC/1131 复核留痕合并。

### 1.4 事务所制度应补的 5 条

1. **AI 工具准入白名单**（禁止私自用未评估的外部工具；新模型/版本升级须完成风险评估）
2. **数据分级分类**：高敏感数据禁止上传云端；与云厂商签 DPA，**明确禁止用审计数据训练模型**
3. **部署方式按敏感度选**：公共云 / 私有化 / 本地推理，分级授权
4. **人工复核为强制节点**：AI 生成的底稿与数据分析结果**必须经人工复核**才能作为审计证据
5. **数字足迹**：自动记录 AI 辅助判断的输入数据、算法版本、推理路径（可追溯、可解释）

### 1.5 国际动态（对标参考，不影响国内执业）

> **2026-08-05 后的最新进展见 〇C**（ISA 330/500/520 征求意见稿已发布，评论期至 2026-12-15）。下表为背景沿革。

## 二、企业用 AI 造假：识别方法

### 2.1 造假形态分层（决定用什么查法）

| 层级 | 手法 | 典型标的 | 识别难度 |
|---|---|---|---|
| L1 **文本生成** | LLM 编造合同、会议纪要、尽调说明、询证函回复说明 | Word / PDF 文本 | 中（逻辑与交叉核对可破） |
| L2 **票据合成** | 模板+生成模型做发票、完税证明、银行回单、对账单 | 图片 / PDF | 高 |
| L3 **要素篡改** | Inpainting / 内容识别填充改金额、账号、日期、印章 | 原 PDF / 图片 | 高 |
| L4 **签章伪造** | GAN/Diffusion 生成手写签名、印章；deepfake 人脸用于视频尽调访谈 | 图片 / 视频 | 极高 |
| L5 **包裹拦截** | 拦截函证、伪造回函快递与邮箱域名（配合 L1-L4） | 函证流程 | 极高（程序防） |

### 2.2 五层识别技术（从易到难，逐层叠加）

**① 来源与渠道层（最有效、成本最低 —— 优先做）**
- 数电票：**只认 XML/OFD 原件**，逐张上**全国增值税发票查验平台**/电子发票服务平台验真（数电票**开票即上传**，AI 做不出"能验真"的票）
- 银行：网银/银企直连取数、**银行函证电子平台**、柜台打印盖鲜章，不收客户下载件
- 税务：电子税务局官方渠道核实完税证明（真实案例即栽在"网上软件做的完税证明"）
- 物流/仓储：穿透运单、磅单、GPS、第三方仓单，而非客户上传件

**② 密码学与结构层（能"证明"而非"怀疑"）**
- **数字签名验签**：OFD/PDF 电子签名 + 时间戳；签名破损/部分覆盖 = 签后篡改
- **PDF 增量更新检查**：伪造编辑常以增量更新保存，旧对象版本仍在（用 pdfid / 对象流工具）
- **哈希比对**：与存档/原始下发件比 SHA-256，任一字节改动即破
- 数电票走电子凭证会计数据标准（**财会〔2025〕9号**）接收-**验签**-解析-报销-入账-归档

**③ 元数据与出处层（快筛，30 秒/份）**
- `exiftool` 看：创建/修改时间、生成软件、Producer、ICC 色彩配置、压缩链
- 红旗：①**元数据被清空**（正常业务单据没必要擦）；②AI 生成合成内容按《标识办法》须嵌入含 **AIGC** 字段的隐式标识（2025-09-01 起强制）——**查到即实锤**；③声称扫描件却带桌面截图工具特征；④C2PA/Content Credentials 清单显示 Firefly 等生成式工具用过

**④ 像素与频域层（对付 L2-L4）**
- **ELA（错误等级分析）**：重存后局部亮度异常 = 该区域压缩历史不同（FotoForensics / Forensically 免费）
- **JPEG Ghost / 缩略图比对**：EXIF 缩略图与主图不符 = 必被改过
- **FFT 频谱**：GAN 上采样留周期性网格峰；扩散模型留噪声残差模式
- **PRNU**：AI 图**没有**相机传感器指纹（需同设备参考图）
- **字体度量**：替换字符的 kerning/基线/抗锯齿与原机构生成管线不符
- **神经元检测器筛查**：TruFor / CNNDetect / Hive / Copyleaks（报"筛查指标"而非"鉴定结论"）

**⑤ 逻辑与交叉层（抓 L1 与整体矛盾）**
- **单据间勾稽**：发票—合同—入库—付款—物流—报关，八到十二份单据同时保持完美一致，超出现有生成器能力
- **数学验证**：合计对不上、流水余额不连续、税率/征收率错（手改数字必出错）
- **第三方交叉**：工商/税务/海关/征信/物流/电力能耗 vs 申报收入
- **批处理痕迹**：同一 IP/设备批量上传、PDF Producer 与字体子集相同、创建时间集中在几分钟内、金额凑整、发票连号异常

### 2.3 按证据类型的"最低识别动作"清单

| 证据 | 最低动作（不做即视为程序不到位） |
|---|---|
| 增值税发票 | 取 XML/OFD 原件 + 全国增值税发票查验平台逐张验真 + 查重（防同一张票重复报销） |
| 银行回单/对账单 | 银企直连/网银自行导出 或 电子函证平台；核对印章、流水号、余额连续性 |
| 完税证明 | 电子税务局官方渠道核验 |
| 大额合同 | CA 数字证书+时间戳电子签原件；比对用印审批流与 OA 日志 |
| 出入库/验收单 | 调 ERP 单据流水（含操作人、时间戳），不收上传扫描件 |
| 函证 | 电子函证平台；**回函后电话向对方财务/银行核验**（防拦截与伪造回函） |
| 访谈/视频尽调 | 主动活体检测（眨眼/转头/点头），或改线下；警惕背景文字乱码、耳饰不对称、光影不一致 |
| 电子资料批量 | 批量跑元数据+哈希+AI 概率分（50 张/批），命中再单张深查 |

### 2.4 免费工具清单（可立即用）

| 用途 | 工具 | 说明 |
|---|---|---|
| 元数据 | `exiftool`（命令行）/ Jeffrey's Metadata Viewer | 中电票、图片通用 |
| ELA / Ghost | FotoForensics、Forensically | 免注册 |
| 综合 | InVID WeVerify（浏览器插件） | 反搜 + 元数据 + 视频关键帧 |
| AI 概率 | Hive Moderation、Illuminarty、Copyleaks | 有免费额度 |
| 出处核验 | contentcredentials.org/verify（C2PA） | 查是否 AI 工具生成 |
| 发票 | 全国增值税发票查验平台 | 官方 |
| 文件完整性 | PowerShell `Get-FileHash -Algorithm SHA256` | 取证留痕 |

### 2.5 发现疑似造假后的取证与应对（关键，别打草惊蛇）

1. **先固化**：收到即算 SHA-256 并记录时间、来源、经手人（链 of custody），**不要在原件上操作**
2. **复制件分析**：所有检测在副本上做
3. **留痕内容**：工具名+版本+参数、输出截图、检测时间、操作人
4. **结论措辞**：写"筛查指标显示…"，**不写"经 AI 检测确认为伪造"**（司法鉴定口径：须有方法学、误报率、盲测验证）
5. **升级路径**：向项目合伙人/质控报告 → 评估对**管理层诚信**的影响（CSA 1141）→ 重新评估舞弊风险与审计策略 → 考虑对审计意见/沟通事项的影响 → 必要时与治理层沟通或解除业务约定

### 2.6 客户侧防线（写管理建议书直接用）

## 三、风险评估阶段可直接用的红旗清单（CSA 1141 补充维度：电子证据环境）

- [ ] 业务单据高度数字化，但 IT 控制弱（可后补录、无审计追踪、日志可改）
- [ ] 报销/审批/对账大量依赖**截图、邮件附件、自行下载 PDF** 作为唯一依据
- [ ] 关键证据"自证"为主（对账单是自家系统导出、回单是出纳下载）
- [ ] 存在**函证被拦截/回函异常**迹象（见 [[2026-大华所-东方集团-农产品融资性贸易审计失败]] 之外的广道数字案：监事开发软件批量做假发票假回单并拦截询证函）
- [ ] 供应商/客户为**新设、无社保、地址雷同**的壳主体
- [ ] 一句话反问："这张单据是从哪个**权威系统**直出的？"——答不上来即升级
