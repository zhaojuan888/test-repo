# 标签规范（受控词表）

> 目的：消除「审计AI / AI审计 / 人工智能审计」式命名漂移，让 Dataview 能跨文件夹稳定聚合。
> 所有 `2-知识库` 下的笔记 frontmatter 必须遵循本规范。新增标签前先来此处对齐，不要自造。

## 一、必填字段（强制）

| 字段 | 取值约束 | 说明 |
|---|---|---|
| `type` | 见下方受控词表 | 内容大类，决定归哪个文件夹 |
| `tags` | 数组，取自受控词表 | 跨库检索维度，**至少 1 个** |
| `created` | `YYYY-MM-DD` | 写入日期 |
| `status` | `草稿 / 待归类 / 待复核 / 可用 / 归档` | 质量状态；`待归类`=staging 刚转出的半成品，归类完成即改 `可用` |
| `source` | 字符串 | 来源文件或 URL（溯源） |

可选：`standard`（准则编号，如 CAS-14）、`sensitive`（敏感标记）、`converter`（转换工具）、`industry`（行业名）。

## 二、type 受控词表

```
准则笔记          会计准则逐条解读（CAS-1/3/6/8/13/14/17/21/22/25/1141…）
核查指引          审计程序 / 核查方法 / 控制测试
行业研究          某行业的会计核算与审计风险
企业财务规范      企业自身如何建账、建内控、建流程（与审计互为镜像）
AI工具与系统      审计/财务 AI 工具、平台、系统软件情报
模板              模板 / 规范类文件本身
情报             资讯、文章、外部来源的筛选整理
资料-待分类      staging 转换产出的半成品（待人归类）
```

## 三、tags 受控词表（可分维度，允许多选）

**通用维度**
- 审计视角：`审计程序` `风险点` `核查方法` `控制测试` `实质性程序` `底稿`
- 企业视角：`核算规范` `内控` `流程标准化` `税务合规` `业财数字化` `会计政策`
- 质量：`草稿` `待复核` `可用` `归档`

**专业维度**
- 准则：`CAS收入` `CAS金融工具` `CAS合并` `CAS减值` `CAS租赁` `新保险合同` `政府补助`
- 领域：`IPO` `FDD` `反舞弊` `税务` `内控` `函证` `截止测试` `抽样`
- 行业：`汽车` `房地产` `典当` `电商` `保险` `银行业` `制造业` `政府会计`

**来源维度**
- `staging`（自动转换产出） `web`（联网检索） `IMA`（知识库检索） `MinerU`（OCR 提取）
- `capture`（视频号/B站/公众号/抖音/小红书等 App 内检索后丢入收件箱的链路补采） `截图`（截图类情报，需本地 OCR）
- 捕获平台标签（鼓励取自小集合，自由但建议统一）：`视频号` `公众号` `b站` `抖音` `小红书` `知乎`，写入 frontmatter `platform:` 字段并加对应 tag

## 四、命名约定

1. 笔记文件名：`行业-会计核算与审计风险.md`（行业研究）、`X准则-笔记.md`（准则）、`XXX-核查指引.md`（程序）。
2. 企业财务规范对照笔记：`行业-企业财务规范对照.md`，Frontmatter 加 `industry::` 与双向链接回审计笔记。
3. 同一主题审计侧与企业侧**互链**：审计风险笔记末尾 `> 企业侧对照：[[行业-企业财务规范对照]]`。

## 五、禁止

- 不在受控词表外自造近义词标签（如已有 `内控`，不得另写 `内部控制` `内控制度`）。
- 不写空 tags。
- `status` 不得长期停留在 `草稿` 不更新——归类完成即改 `可用`。

## 六、捕获与补采工作流（0-收件箱 → 视频号/B站盲区）

> 视频号 / B站 / 公众号 等平台在 Web 检索盲区，需在 App 内检索后把**链接或截图**丢进
> `0-收件箱`，由 `8-系统/staging_convert.py` 自动转成待整理笔记（补采）。

**丢入形态 → 脚本处理：**
| 丢入物 | 形态 | 生成笔记 | frontmatter |
|---|---|---|---|
| 链接 | `.url` / `.webloc` 快捷方式，或仅含一个 URL 的 `.txt`/`.md` | `情报` 型「待抓取」笔记 | `type:情报` + `tags:[staging,web,capture,平台]` + `platform:` + 原始链接写入 `source` |
| 截图 | `png/jpg/...` | 占位笔记 + 入 `_needs_ocr.txt` 队列 | `tags:[staging,MinerU,capture,截图]`；`source` 为相对路径，`![[原图]]` 嵌入 |
| 文章/文件 | `docx/xlsx/csv/pdf（文本层）/md` | 对应 md 半成品 | `type:资料-待分类` + `tags:[staging]` |

**补采闭环：**
1. App 内检索 → 复制链接 / 截屏 → 存为文件丢入 `0-收件箱`。
2. 跑 `python 8-系统/staging_convert.py --once`（或 `--watch` 常驻）。
3. 链接笔记：人工点开链接读正文，或经本地抓取工具（如公众号→md 技能）补全后改 `status:可用` 并归类。
4. 截图笔记：用本地 MinerU 技能 OCR → 把正文并入笔记 → 改 `status:可用` 并归类。
5. 每周整理：清空 `0-收件箱/_out` 半成品，有价值者拆为原子笔记入 `2-知识库/`。

**红线：** 链接/截图可能含客户敏感信息，全程本地；截图 OCR 只用本地 MinerU，禁止上传公网。
