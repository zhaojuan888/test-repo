# CLAUDE.md — 审迹知识库 AI 集成指令

> 此文件在每次 AI 会话启动时自动加载，告诉 AI 如何理解和操作这个知识库。

## Vault 架构

```
审迹知识库/
├── 0-收件箱/          ← 随手捕获，每周整理到 2-知识库
├── 1-项目/            ← 活跃审计项目（PARA Projects）
├── 2-知识库/          ← Zettelkasten 原子笔记（核心知识库）
│   ├── 会计准则/      ← 企业会计准则
│   ├── 税法/          ← 税法条文 + 税务专题
│   ├── 审计程序/      ← 审计程序 + 方法论
│   ├── 处罚案例/      ← 处罚案例 + 审计失败分析
│   └── 行业研究/      ← 行业知识（医药/制造/建安等）
├── 3-知识地图/        ← Map of Content 自动聚合页（Dataview 驱动）
├── 4-模板/            ← 笔记模板
├── 5-参考资料/        ← PDF、法规文件等参考资料
├── 6-每日笔记/        ← 每日笔记（YYYY-MM-DD.md）
├── 7-归档/            ← 已完成项目归档
└── 8-系统/            ← 配置文件、附件、脚本
```

## 笔记约定

### 文件命名
- 准则笔记：`CAS-14-收入.md`
- 案例笔记：`2025-利安达-江平生物-存货审计失败.md`
- 税务笔记：`增值税-留抵退税-骗税风险.md`
- 审计程序：`存货-盘点程序-关键要点.md`
- 每日笔记：`YYYY-MM-DD.md`（在 6-每日笔记/）

### Frontmatter 标准（Obsidian Properties）

每次创建笔记时必须包含以下 properties：

```yaml
---
type: concept | case | procedure | tax_clause | industry | project | daily
category: [审计失败, 存货审计]  # 可多值
standard: [CAS 1311]            # 关联准则
tags: [标签1, 标签2]
status: evergreen | draft | review-needed | archived
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

### 链接规则
- **双向链接**：`[[笔记名]]`，不用路径
- **每条原子笔记至少链接 2 篇其他笔记**
- **MOC 页面只能用 Dataview 查询，不手写列表**
- **每日笔记必须链接当天涉及的项目、案例、准则**

## 核心工作流

### 日终捕获（5 分钟）
打开 6-每日笔记/ 当日笔记，记录：
- 今天经手的项目
- 新发现的风险点 / 准则判断
- 看到的处罚案例 / 法规更新

### 周整理（20 分钟，周日）
1. 清理 0-收件箱/
2. 把本周 daily notes 中有价值的条目拆成原子笔记 → 2-知识库/
3. 给新笔记打 type/category/tags
4. 确保每条新笔记至少链接 2 篇已有笔记

### 月度回顾（30 分钟）
打开 3-知识地图/ 检查：
- 孤儿笔记（无链接）→ 补链接
- status: review-needed → 复习或更新
- 过期准则 → 标记 archived

## 不要做的事
- ❌ 不要创建超过 3 层深的文件夹
- ❌ 不要在 MOC 页面手写链接列表（Dataview 自动生成）
- ❌ 不要完美主义——先记下来，周末再整理
- ❌ 不要删除笔记——移到 7-归档/
